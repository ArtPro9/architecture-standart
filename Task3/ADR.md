### <a name="_qmphm5d6rvi3"></a>**Решение**

[Диаграмма контекста](Context.puml)  
[Диаграмма контейнеров](Container.puml)

- Клиенты могут открывать депозиты через интернет-банк или публичный сайт. Заявки направляются в сервис депозитов, который сохраняет их в базе данных и отправляет в очередь сообщений.
- Колл-центр получает заявки из очереди, обрабатывает их и отправляет подтвержденные заявки обратно в сервис депозитов.
- Сервис депозитов запрашивает согласование ставок через сервис согласования ставок, который взаимодействует с базой данных АБС для получения и сохранения информации о ставках.
- После обработки заявки клиент получает SMS-уведомление о статусе своей заявки.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

В качестве брокера сообщений можно рассмотреть RabbitMQ вместо Kafka.
Отказались в пользу Kafka из-за лучшей масштабируемости и отказоустойчивости.

Как альтернативную базу данных можно рассмотреть PostgreSQL. 
Выбран Oracle, потому что уже используется в компании и есть экспертиза.

**Недостатки, ограничения, риски**

1. База данных АБС не может масштабироваться горизонтально.
Может быть проблемой при большом росте онлайн-заявок.

2. Ручная обработка заявок в MVP. 
Может ухудшить восприятие скорости работы сервиса.

3. Обновление монолита все еще долгий процесс из-за накопленного техдолга.
